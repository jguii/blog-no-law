# Runbook: inventário e rotação de segredos

Este repositório é público (D-07). Este documento cita segredos só pelo **nome**; nenhum valor entra aqui, nem em chat, issue, PR ou log. Para gravar um secret, passe o valor pelo prompt do `gh secret set ... --env production --repo jguii/blog-no-law` (nunca como argumento da linha de comando).

## Segredo vazou (D-07)

O repositório é público: o que foi publicado pode ter sido clonado ou indexado. **Nunca tente "despublicar"** (reescrever histórico, apagar o commit, o log ou o comentário) como correção: isso não desfaz a cópia de ninguém.

1. **Rotacione primeiro**, na hora, pela linha da tabela acima. O segredo antigo precisa deixar de valer antes de qualquer outra coisa.
2. **Revise o log** do que o segredo dava acesso, desde o momento do vazamento:
   - banco: Supabase -> Logs (Postgres e API) e uma conferência com `verify-db-security.mjs` (papéis, RLS, privilégios);
   - deploy hook: Render -> Events (deploys que você não disparou);
   - token de backups: Security log da conta GitHub e as releases do `blog-no-law-backups` (apagadas ou criadas fora do horário);
   - Actions: os runs recentes de `Backup` e `Deploy API`.
3. **Corrija a causa** (o passo que imprimiu ou gravou o valor) por PR, com teste.
4. Registre o incidente (data, segredo, janela de exposição, rotação feita) no PR da correção, sem o valor.
