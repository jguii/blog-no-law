## Phase Goal

**As a** desenvolvedor do Blog No Law, **I want to** ter um esqueleto Next.js + NestJS + Supabase publicado em produção e protegido por testes, CI e backups, **so that** toda funcionalidade nasça testada e implantada desde o primeiro commit.

<objective>
Criar o banco de produção no Supabase (`us-east-1`), aplicar a migration baseline nele e provar a segurança em produção: RLS em todas as tabelas, `app_api` sem bypass e PostgREST anônimo sem leitura. Este plano contém o **[BLOCKING] schema push** da fase (`prisma migrate deploy`, nunca `prisma db push`, porque o RLS e os papéis são SQL puro dentro da migration).

Purpose: o 01-11 sobe a API na Render apontando para este banco como `app_api`; o 01-12 automatiza o `migrate deploy` no pipeline; o 01-13 faz o backup dele.

Output: projeto Supabase criado, migration aplicada, credencial `app_api` gerada, scripts de verificação e runbook.

Este plano roda em paralelo com o 01-05 (sem arquivos em comum; o 01-05 usa o banco `blog_test` local, e o 01-06 usa o banco de produção e, no teste da Task 3, só um papel próprio `app_api_pwtest` no Postgres local, sem tocar em `blog_test` nem no papel `app_api`). Ordem das tarefas: o checkpoint humano vem antes do tracer porque o tracer precisa do projeto criado; o tracer é a primeira tarefa de implementação.
</objective>
