<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> proxy da plataforma -> API | headers como `X-Forwarded-For` e `Origin` são controlados pelo cliente |
| API -> stdout (painel da plataforma) | logs podem ser lidos por quem acessa o painel |
| API -> Sentry (SaaS) | eventos de erro saem para terceiro |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-14 | Information disclosure | logs pino | high | mitigate | `redact` com censor `[REDACTED]` em authorization/cookie/set-cookie/token/password/secret; teste procura o token literal |
| T-01-15 | Spoofing | IP do cliente via `X-Forwarded-For` | medium | mitigate | `trust proxy` = número de hops (default 1, D-02); teste prova que o valor forjado à esquerda é ignorado; sonda real no 01-11 |
| T-01-16 | Information disclosure | rota `/_debug/error` | medium | mitigate | 404 por padrão; só liga com `DEBUG_ROUTES_ENABLED=true` (usado apenas no boot da Railway, 01-11); resposta 500 sem stack |
| T-01-17 | Tampering | headers de segurança e CORS | medium | mitigate | Helmet com CSP `default-src 'none'`, `frame-ancestors 'none'`; CORS só para origens exatas, `credentials: false` |
